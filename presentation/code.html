chapitre 1L'architecture en couches

01

Séparer par responsabilité, pas par fichier

structure

Chaque dossier a UNE mission et n'en connaît pas d'autre.

Ataraxia est découpé en 4 dossiers, chacun avec une responsabilité étanche :

  • voice/ — capter et jouer de l'audio (STT + TTS)
  • ai/ — les prompts LLM et la boucle de dialogue
  • marble/ — le client de l'API Marble
  • orchestrator/ — assemble tout (serveur FastAPI + front web)

Règle qu'on tient : ai/ ne sait rien de marble/, marble/ ne sait rien de FastAPI. Seul orchestrator/ connaît tout le monde.

Pourquoi : remplacer Marble par un autre moteur ne touchera QUE marble/client.py. Changer de LLM ne touchera QUE ai/conversation.py. Chaque couche peut évoluer sans casser les autres.

chapitre 2Backend Python — FastAPI

02

Un endpoint = un décorateur + une fonction typée

python · fastapi

Le décorateur enregistre la route ; la fonction reçoit les params, renvoie du JSON.

Extrait de orchestrator/server.py :

@app.get("/api/themes")
def themes() -> dict:
    return {"themes": list_themes(), "total_turns": TOURS_PAR_SEANCE}

FastAPI se charge de tout : sérialiser le dict retourné en JSON, définir l'entête Content-Type: application/json, gérer les codes HTTP. La type hint -> dict est utilisée par FastAPI pour générer la doc OpenAPI (disponible sur /docs).

03

Pydantic valide les entrées automatiquement

python · pydantic

Un modèle Pydantic = un contrat sur ce que le client DOIT envoyer.

class StartReq(BaseModel):
    theme: str

@app.post("/api/session/start")
async def start(req: StartReq) -> dict:
    if req.theme not in list_themes():
        raise HTTPException(400, "Thème inconnu")
    ...

Si le client envoie {"themme": "..."} (typo), FastAPI répond 422 Unprocessable Entity automatiquement, avec un message explicite pointant le champ manquant. Zéro validation à écrire à la main.

04

Upload de fichier — UploadFile + multipart

python · fastapi

Recevoir un blob (audio, image, PDF) = UploadFile + File(...).

@app.post("/api/session/{sid}/turn")
async def turn(sid: str, audio: UploadFile = File(...)) -> dict:
    data = await audio.read()      # lit le fichier en RAM
    if not data:
        raise HTTPException(400, "Audio vide")
    ...

Côté client, on envoie via FormData :

const fd = new FormData();
fd.append("audio", blob, "user.webm");
await fetch(url, { method: "POST", body: fd });

Ne pas mettre Content-Type: application/json dans les headers — FastAPI attend du multipart/form-data et le browser positionne la bonne valeur automatiquement quand on passe un FormData.

05

Type hints avancés : Literal pour les enums

python

Contraindre un paramètre à une liste finie de valeurs, sans créer une classe Enum.

from typing import Literal

Theme = Literal["anxiete", "stress", "humeur", "sommeil", "estime", "autre"]

def opening_question(theme: Theme) -> str:
    return OPENING_QUESTIONS[theme]

Les type-checkers (mypy, pyright, VS Code) refuseront opening_question("foo") en amont de l'exécution. Léger, sans dépendance.

chapitre 3Backend Python — asynchrone

06

async / await — ne pas bloquer pendant l'attente

python

Pendant qu'on attend une réponse réseau, le serveur peut traiter d'autres requêtes.

Une route async def peut faire await sur n'importe quelle opération I/O. Uvicorn ne bloque pas — il libère le thread pendant l'attente.

async def _tts_b64(text: str) -> str | None:
    tmp = Path(tempfile.gettempdir()) / f"ataraxia_tts_{uuid.uuid4().hex}.mp3"
    await tts.synth_async(text, tmp)   # await = le serveur reste dispo
    return base64.b64encode(tmp.read_bytes()).decode()
07

asyncio.gather — paralléliser deux appels indépendants

python

Deux appels TTS lancés séquentiellement = 2× le temps. En parallèle = le temps du plus long.

# Les deux TTS n'ont aucune dépendance entre eux → on parallélise
desc_audio, close_audio = await asyncio.gather(
    _tts_b64(enriched["description"]),
    _tts_b64(INVITE_CLOSE_TEXT),
)

Sans gather, il faudrait desc = await _tts_b64(...); close = await _tts_b64(...) — soit ~2× 800 ms = 1.6 s au lieu de 800 ms.

Piège : n'utiliser gather QUE si les tâches sont indépendantes. Si close a besoin du résultat de desc, il faut les enchaîner.

chapitre 4Backend Python — erreurs & fallback

08

Exceptions personnalisées pour typer les erreurs d'API externe

python

Une classe d'exception par famille d'erreur métier = du except propre à l'appel.

class MarbleAPIError(RuntimeError):
    def __init__(self, status_code: int, detail: str = ""):
        self.status_code = status_code
        self.detail = detail
        super().__init__(f"Marble API {status_code}: {detail}")

class MarbleOutOfCreditsError(MarbleAPIError):
    def __init__(self, detail: str = ""):
        super().__init__(402, detail or "Insufficient API credits")

Ensuite dans le endpoint, on peut catcher spécifiquement :

try:
    world = _marble.generate_world(desc, details)
except MarbleOutOfCreditsError as e:
    raise HTTPException(402, detail={"code": "marble_out_of_credits", ...})
except MarbleAPIError as e:
    raise HTTPException(502, detail={"code": "marble_api_error", ...})

Le front reçoit un code métier structuré (marble_out_of_credits) et peut afficher un message adapté avec un lien vers le billing.

09

Le "graceful fallback" — dégrader plutôt que crasher

python

Si un service externe refuse, on continue avec une version dégradée au lieu de renvoyer un 500.

Le LLM peut refuser une génération JSON (safety trigger). Sans protection : HTTP 500 côté user. Avec fallback :

def enrich_world_description(self, user_input: str) -> dict:
    text = (user_input or "").strip()
    if not text:
        return {"description": "", "details": {}}
    try:
        raw = self._chat(msgs, temperature=0.8, json_mode=True)
        return parse_world_description(raw)
    except Exception as e:
        # Groq a refusé (safety) OU JSON invalide OU timeout.
        # On retombe sur la description brute — Marble s'en accommode.
        print(f"[enrich] fallback — {type(e).__name__}: {e}")
        return {"description": text, "details": {}}

Principe : chaque appel externe qui peut échouer sans être bloquant devrait avoir un plan B. L'user ne devrait jamais voir un 500 pour un truc récupérable.

10

HTTP status codes — pas juste 200 et 500

web

Bien choisir le code = information machine-readable pour le client.

  • 400 Bad Request — l'input est invalide (ex : session pas encore terminée)
  • 402 Payment Required — rarement utilisé, parfait pour « crédits épuisés »
  • 404 Not Found — la ressource n'existe pas (session inconnue)
  • 422 Unprocessable Entity — Pydantic l'utilise pour un body qui ne match pas le schéma
  • 500 Internal Server Error — bug côté serveur, jamais volontaire
  • 502 Bad Gateway — un service upstream (Marble, Groq) a échoué

Ataraxia distingue explicitement 402 (crédits) et 502 (autre erreur Marble) — ça permet au front d'afficher un message d'action utile.

chapitre 5LLM & prompts

11

Un system prompt = un rôle et des règles

llm

Le LLM est un acteur. Le system prompt lui dit qui il joue.

Extrait du prompt psy (ai/prompts.py) :

PSY_SYSTEM_PROMPT = """Tu es le compagnon d'écoute d'Ataraxia [...]
- Français, deuxième personne du singulier, voix calme, empathique.
- À CHAQUE tour, tu commences par reformuler [...] puis tu poses UNE
  seule nouvelle question, adaptée à ce qu'elle vient de partager.
- Ne juge jamais, ne minimise jamais, n'invente rien sur elle.
- Si la personne exprime une détresse aiguë [...] tu l'invites
  immédiatement à contacter le 3114 [...]
"""

Trois choses qui marchent pour un system prompt :

  • Impératifs clairs (« Tu POSES UNE seule question ») — pas de « idéalement »
  • Interdictions explicites (« n'invente jamais »)
  • Cas critiques traités séparément (« si détresse → 3114 »)
12

response_format: json_object — forcer du JSON

llm · groq

Sans, le LLM peut répondre en prose. Avec, il DOIT renvoyer un JSON valide.

r = client.chat.completions.create(
    model="openai/gpt-oss-120b",
    messages=msgs,
    temperature=0.8,
    response_format={"type": "json_object"},  # ← ici
)

Piège : si le modèle refuse (safety) et répond « I'm sorry, I can't fulfill that request. », ce n'est pas du JSON. Groq renvoie alors 400 json_validate_failed — d'où l'utilité du fallback vu en notion 09.

13

Prompt = source de qualité produit

llm · design

Un prompt trop générique produit du contenu générique. Une contrainte forte débloque la spécificité.

Le prompt d'enrichissement initial disait juste « Fidèle à l'intention ». Résultat : le LLM proposait toujours plage ou forêt. Corrigé en :

# Extrait de WORLD_DESCRIPTION_SYSTEM_PROMPT
"""RÈGLE ABSOLUE — LE LIEU EST CELUI DE LA PERSONNE :
Le lieu qu'elle nomme (café, grenier, atelier, phare, cathédrale...)
c'est CE lieu, exactement, que tu décris. TU NE LE REMPLACES JAMAIS
par un lieu plus 'générique' comme une plage ou une forêt, sauf si
elle-même a nommé une plage ou une forêt."""

Effet mesuré : « café en terrasse italienne » → lieu_type: "café en terrasse italienne" (avant : "plage"). Une contrainte forte + une liste d'exemples débloque la spécificité.

14

Deux modèles pour deux usages

llm · perf

Modèle gros pour la qualité, modèle petit pour la latence — même provider, deux endpoints.

DEFAULT_CHAT_MODEL = "openai/gpt-oss-120b"  # psy + enrichissement (qualité)
DEFAULT_FAST_MODEL = "openai/gpt-oss-20b"   # sentiment JSON (rapide)

L'analyse de sentiment n'a pas besoin d'une prose élégante — juste un JSON strict. Le petit modèle suffit largement et divise la latence par ~3.

chapitre 6Frontend — Web Audio (le VAD)

15

Détection d'activité vocale (VAD) via RMS

javascript · web audio

Calculer l'énergie audio (RMS) toutes les 100 ms ; au-dessus d'un seuil = parole ; sous le seuil pendant 1.5 s = silence → on coupe.

const audioCtx = new AudioContext();
const source = audioCtx.createMediaStreamSource(stream);
const analyser = audioCtx.createAnalyser();
analyser.fftSize = 512;
source.connect(analyser);
const buf = new Float32Array(analyser.fftSize);

const interval = setInterval(() => {
  analyser.getFloatTimeDomainData(buf);
  let sum = 0;
  for (let i = 0; i < buf.length; i++) sum += buf[i] * buf[i];
  const rms = Math.sqrt(sum / buf.length);
  // rms > 0.015 = parole détectée ; rms bas > 1500 ms = silence
}, 100);

Pas besoin de bibliothèque tierce. L'AnalyserNode fait le boulot. Les seuils (SPEAK_THRESHOLD = 0.015, SILENCE_MS = 1500) sont ajustables selon l'environnement.

Piège classique : quand l'audio TTS joue en même temps, le micro capte le haut-parleur (echo). Solution : activer echoCancellation: true à l'ouverture du micro, et augmenter le seuil pendant la lecture.
16

MediaRecorder — enregistrer un blob audio

javascript

L'API standard du navigateur pour capter le micro en WebM Opus.

const mimeType = MediaRecorder.isTypeSupported("audio/webm;codecs=opus")
  ? "audio/webm;codecs=opus"
  : "audio/webm";
const recorder = new MediaRecorder(stream, { mimeType });
const chunks = [];
recorder.ondataavailable = e => { if (e.data.size > 0) chunks.push(e.data); };
recorder.onstop = async () => {
  const blob = new Blob(chunks, { type: mimeType });
  await sendTurn(blob);
};
recorder.start(200);  // chunks toutes les 200 ms

WebM Opus est le format le plus universellement supporté par les navigateurs, et Whisper (côté serveur) le lit sans conversion.

Piège : sur iOS Safari, le mimeType peut ne pas être supporté ; il faut fallback sur "audio/mp4". Utiliser MediaRecorder.isTypeSupported() avant de créer l'instance.

chapitre 7Frontend — état, fetch, audio

17

Un seul objet state global partagé

javascript · design

Pas de framework ? Un seul objet state centralise tout ce qui doit être partagé entre handlers.

const state = {
  sessionId: null,
  worldId: null,
  totalTurns: 5,
  recording: false,
  currentAudio: null,
  mode: "psy",        // "psy" | "quick"
  pendingRevealSkip: null, // closure : que faire au skip
};

Avantage sur les frameworks à hooks : très lisible pour un projet à cette échelle, aucun besoin de re-render, aucune magie. Un handler mute state, un autre le lit — c'est tout.

Quand ça craque : dès que plusieurs vues doivent auto-refresh sur une mutation, ce pattern devient pénible. Là on saute vers React/Svelte/etc.

18

Lire un audio base64 sans le télécharger

javascript

Le backend renvoie l'audio en base64, on le colle dans une data-URL, le browser lit directement.

function playAudioB64(b64, onEnded) {
  if (state.currentAudio) {
    try { state.currentAudio.pause(); } catch (_) {}
  }
  const audio = new Audio("data:audio/mp3;base64," + b64);
  state.currentAudio = audio;
  audio.onended = onEnded;
  audio.play().catch(err => console.warn("lecture bloquée :", err));
}

Pas de fetch, pas d'URL temporaire, pas d'<audio src> dans le DOM. Le blob voyage en JSON à l'intérieur de la réponse API — un seul aller-retour réseau.

Piège : audio.play() retourne une Promise et peut être rejetée si l'user n'a pas encore interagi (autoplay policy). C'est pourquoi on .catch systématiquement.
19

Cleanup rigoureux avec try/catch autour de chaque libération

javascript

Oublier un cleanup laisse le micro allumé (icône rouge du browser) et bouffe la batterie.

const cleanup = () => {
  try { clearInterval(interval); } catch (_) {}
  try { stream.getTracks().forEach(t => t.stop()); } catch (_) {}
  try { audioCtx.close(); } catch (_) {}
};

Chaque try/catch individuel : si une libération échoue (ex : le contexte est déjà fermé), les suivantes s'exécutent quand même. Sans les try/catch séparés, une seule erreur bloquerait tout le cleanup.

chapitre 8CSS moderne

20

CSS custom properties (variables)

css

Un token défini une fois, réutilisé partout — changer la palette = éditer 6 lignes.

:root {
  --terra: #b06b46;
  --ink: #2b1e12;
  --card: rgba(255, 250, 240, 0.85);
  --radius: 14px;
}
.btn { background: var(--ink); color: #f8ecd6; border-radius: var(--radius); }

Contrairement à SCSS, les variables CSS sont runtime — modifiables via JavaScript, réactives au dark mode, cascadables par composant.

21

Grid responsive sans media query

css

auto-fit + minmax = colonnes qui s'adaptent seules.

.tech-grid {
  display: grid;
  gap: 18px;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
}

Sur écran large : 3-4 colonnes de 280 px min. Sur mobile : 1 colonne pleine largeur. Aucune media query, le grid gère seul.

22

clamp() pour la typo fluide

css

Une seule règle qui gère min, préférée, max — le browser interpole selon la largeur.

h2 { font-size: clamp(28px, 4vw, 48px); }
/* jamais < 28, jamais > 48, sinon 4% de la largeur du viewport */

Remplace 3-4 @media pour la même typo. Plus lisible, plus maintenable.

chapitre 9Concepts web & réseau

23

HTTPS requis pour getUserMedia

web · sécurité

Sans HTTPS, le browser refuse l'accès au micro. localhost est la seule exception.

C'est pour ça qu'on utilise cloudflared pour exposer Ataraxia au casque VR : ça donne une URL HTTPS gratuite qui contourne cette limitation.

cloudflared tunnel --url http://localhost:8000 --no-autoupdate
# → https://xxx-xxx-xxx.trycloudflare.com
24

CSP frame-ancestors — l'iframe qui ne se laisse pas embarquer

web · sécurité

Un site peut refuser d'être embed dans une iframe cross-origin. Côté client, rien ne le contourne.

Quand on a voulu embarquer un monde Marble dans notre page :

$ curl -sI https://marble.worldlabs.ai/world/xxx
content-security-policy: frame-ancestors 'none'
x-frame-options: DENY

Ces deux headers disent explicitement « aucune iframe cross-origin ne peut m'afficher ». Impossible à outrepasser sans changement côté serveur Marble.

Solution : soit ouvrir dans un nouvel onglet (F0), soit télécharger l'asset panoramique et le rendre soi-même en 360° avec three.js (F2). On a choisi F0.

25

Cache navigateur — le piège du "ça marche pas encore"

web · debug

Modifier app.js ne suffit pas — le browser peut servir la vieille version en cache.

Symptôme : tu modifies le JS, le serveur voit la nouvelle version, mais le browser continue à appeler l'ancien endpoint. C'est le cache HTTP.

Solutions :

  • Hard reload : Ctrl+Shift+R (Windows/Linux) ou Cmd+Shift+R (Mac)
  • Devtools ouvert avec « Disable cache » coché (Network tab)
  • Pour du prod : ajouter un query string versionné : <script src="app.js?v=42">

petit quiz

Tu as compris ?

Six questions rapides sur ce que tu viens de lire. Clique la réponse que tu penses juste — la bonne s'allume en vert.

1. À quoi sert response_format: json_object ?

Il oblige le modèle à retourner un objet JSON valide. Si le modèle refuse (safety), l'API renvoie 400 json_validate_failed — d'où l'intérêt du fallback.

2. Pourquoi asyncio.gather ?

gather lance N coroutines simultanément et attend qu'elles finissent toutes. Utile quand les tâches n'ont pas de dépendance entre elles (par ex. deux TTS).

3. HTTP 402 veut dire…

Statut rare mais reconnu. Ataraxia l'utilise pour signifier « crédits Marble épuisés » et faire réagir le front avec un message + lien billing.

4. Le VAD (Voice Activity Detection) mesure quoi ?

On calcule le RMS (Root Mean Square) de l'onde toutes les 100 ms via un AnalyserNode. Au-dessus d'un seuil = parole ; en-dessous longtemps = silence → coupe.

5. Pourquoi getUserMedia échoue en HTTP simple sur un casque VR ?

Tous les navigateurs modernes refusent l'accès au micro depuis un contexte non sécurisé. localhost est la seule exception. Solution pour le casque : tunnel HTTPS via cloudflared.

6. Le fallback dans enrich_world_description sert à quoi ?

Le fallback transforme un crash 500 en une expérience dégradée mais fonctionnelle : Marble reçoit la description brute au lieu de l'enrichie et génère quand même un monde.
